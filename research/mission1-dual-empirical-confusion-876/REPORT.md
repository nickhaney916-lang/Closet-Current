## Real source-verified problem, without overclaiming accuracy
The default one-model recognition workflow already contains an empirical source-independent manual-review rule `public/recognition-confusion-guard.mjs`, based on an earlier, now-exposed 59-public-photo development study. Its four *predicted* risk types are `Tops:Sweatshirt`, `Tops:Tunic`, `Outerwear:Blazer`, `Shoes:Ankle boots`; the default recognizer makes these `Unknown` and blocks automatically admitting a high-confidence subtype without owner review.

The optional opt-in two-model `public/dual-panel-82.mjs` did not reuse that same risk rule. Consequently the P875 shared-top-five consensus still offered `Use Ankle boots` where both model families agreed — including the **real public-source `commons-0078`** whose historically recorded type is `Sneakers`. This demonstrates a two-model limitation on historically exposed development data, **NOT a sealed blind, independent human-labeled accuracy result**. The code change cannot prove a true classification was repaired.
