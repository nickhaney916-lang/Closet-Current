## What was implemented

Three independently trained alternative weights were actually run, rather than simulated: Marqo FashionSigLIP, general Google SigLIP 2 ONNX, and Marqo FashionCLIP. See `model-candidates.json` and `LICENSES.md` for immutable revisions, publisher evidence, quantized vision/text byte counts and SHA-256. Two models have complete independent text-vector builders and an adapter to the unchanged native recognition engine. This preserves the complete 1,151-label application vocabulary. Precomputed vectors avoid downloading a text encoder onto the phone. They are reproducibly generated, not committed binary weights.

`worker.mjs` is an isolated browser adapter with the native `recognizeWithRecovery` pipeline, whole original-photo framing and exact JPEG digest checks. It has no account or wardrobe-save route. Alternative model results always require review; uncalibrated candidate scores cannot become silent wardrobe saves. Original model and public runtime files are unchanged. Different learned weights and encoder architectures supply the experimental evidence; no source-ID corrections or P835 agreement gate are used.

`color.mjs` measures masked pixels with RGB/HSV and CIE lightness rather than guessing a color through a text prompt. It requires a separately supplied reliable foreground mask, rejects unsafe coverage/transparency/exposure, and reports measured dominance rather than calibrated correctness. **Real-photo color accuracy remains unverified.** No actual instance-segmentation upgrade or new independent mask benchmark is claimed.

## Evidence and limits

The old 16-source P834 cohort remains development-exposed diagnostics. On its 13 garments, unfiltered raw category/subtype predictions were: original CPU model 10/13 and 5/13; Marqo FashionSigLIP whole-frame pilot 11/13 and 6/13; SigLIP 2 4/13 and 2/13; Marqo FashionCLIP 7/13 and 4/13. These raw top-one counts are **not** the original 8/13 Chromium / 7/13 WebKit accepted-category metric. They must never be compared as the same metric. Raw negative top-one rejection was 0/3 for the FashionSigLIP pilot versus 3/3 for the other two pilots. Runtime framing and canonical prompt/vector generation differ from the historical app's selected prompt ensembles; these are candidate pipeline comparisons, not a causal isolation of model weights alone.

The frozen new-photo collection contains 19 original licensed JPEGs: 16 garments and three negatives. Two ambiguous subtype labels are excluded from subtype accuracy, leaving 14. Publisher descriptions were checked by an AI visual reviewer **before inference**. These are **not independent human ground truth or sealed acceptance**. Only tops, shoes and dresses are represented; there are no bottoms/accessory/outerwear acceptance cohorts, no multi-item polygons and no physical-device trials. Three negatives share one archive context. The collection and rejected examples are documented in `new-photos/README.md`.

The new CPU comparison improved raw subtype proposals from 11/14 to 12/14 for FashionSigLIP, while category remained 15/16. This is one corrected sweatshirt example, not a demonstrated population gain. The candidate continued to confuse a boot with heels and a dress with a tunic. Its original threshold logic also produced more uncertain results and a wrong strong shoe prediction. **Do not replace the existing model based on this result.** All candidate outputs are therefore kept in manual review. No target attainment is claimed.

A follow-up held preprocessing and the 47 canonical pilot labels fixed while replacing q8 text embeddings with fp32 text embeddings (vision still q8). Raw subtype stayed 11/14; category regressed from 15/16 to 14/16, with three negatives rejected in both cases. One dress correction was offset by a T-shirt regression. This alternative is also rejected; its result is retained rather than hidden. The pilot's 224-pixel framing differs from the full native-engine adapter; do not pool these experiments.

The actual source-matched Chromium/WebKit comparison is generated by `scripts/parallel67-compare.mjs` into `browser-comparison.json`, including raw predictions, unambiguous subtype denominators, wrong strong proposals, uncertainty, per-category and per-subtype counts, Wilson intervals and measured latency. Candidate review gating and raw proposal accuracy are reported separately; universal review is never counted as a recognition win. The browser inference uses local pinned WASM assets, blocks all external requests and writes photo-free result artifacts. Viewport checks at 320/390/430 concern the diagnostic shell only, **not full-app mobile visual acceptance**. Desktop engines and local model delivery are not Android/iPhone performance measurements. Memory has not been measured on physical devices.

Initial unbounded multi-photo WebKit attempts closed before completing the cohort. Worker-only recycling also failed. The reproducible cohort runner therefore uses five fresh browser processes of at most four photos each. This bounds the evaluation batch but does not repair or pass continuous-session WebKit memory/lifecycle acceptance. The process-close cause was not conclusively identified; it is not a proven out-of-memory diagnosis. Failed attempts do not count as completed browser evidence. Worker-load timings are retained separately from inference timings.

## Reproduce

Install Node 22+ dependencies:

```sh
npm install --no-save --no-package-lock @huggingface/transformers@3.8.1 playwright@1.56.1 sharp@0.34.3
npx playwright install --with-deps chromium webkit
python3 research/parallel67/new-photos/download.py
node scripts/parallel67-build-vectors.mjs marqo
node scripts/parallel67-build-vectors.mjs marqoclip
node scripts/parallel67-warm-model.mjs baseline
node scripts/parallel67-warm-model.mjs marqo
node --test tests/parallel67-independent.test.mjs tests/parallel67-color.test.mjs
node scripts/parallel67-browser-batches.mjs chromium baseline
node scripts/parallel67-browser-batches.mjs chromium marqo
node scripts/parallel67-browser-batches.mjs webkit baseline
node scripts/parallel67-browser-batches.mjs webkit marqo
node scripts/parallel67-compare.mjs
```

The dedicated workflow has read-only repository permissions, an exact P834 ancestry/source-path boundary, native regression tests and actual pinned browser inference. It never deploys. Original JPEGs are recovered from SHA-locked public sources and excluded from Git/artifacts. Pixel manipulation is temporary inference preprocessing; the original bytes remain unchanged.
