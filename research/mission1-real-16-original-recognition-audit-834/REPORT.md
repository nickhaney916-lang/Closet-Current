# Closet Current Mission 1 P834 — genuine FashionCLIP recognition failure audit on 16 existing verified photos

**FAMILY ALPHA HOLD #255. Draft research work, unmerged and undeployed. No personal family images, account, backend, staging or production writes.**

## Why now
Prior recognition-only preparation (P829–P833) gave a safer mobile-width demonstration, honest subtype/color/abstention scoring, a SHA-verified no-account preview package and bounded cancel/restart behavior. However, those browser smoke tests covered just **one publisher T-shirt and one negative** and did **not** establish recognition accuracy across categories. The SegFormer *whole-outfit instance* failure audit P828 is a separate model and does not measure single-garment FashionCLIP recognition.

This priority measures actual unchanged FashionCLIP category/subtype/abstention behavior across a **fixed existing historically reviewed 16-original public Commons cohort**: 13 labeled garments (tops, bottoms including skirts, dresses, jackets and shoes) plus 3 nonclothing controls. Both Chromium and WebKit use the actual signed/pinned unchanged production worker in the isolated no-account preview; 16 original SHA-verified JPEGs per browser, partitioned into predeclared even/odd eight-photo batches. This is more comprehensive **developer-exposed debugging evidence**, not independently double-blinded new-human or phone-population accuracy. The historical labels were already used during prior development, so this work is not a new holdout.

## Evidence contract
- Exactly `benchmark/manifest-holdout-16.json` source ordering and `benchmark/locked-photo-sources.json` original publisher content-addressed SHA-256; 16 unique IDs and all 8 per fixed half. Both source files unchanged from green P833 baseline (CI path allowlist).
- Existing human annotations (category/type) are assigned to the local phone checker **before** any model inference. Generic "Dress" / "Boots" from publisher annotations **cannot be narrowed to a fabricated subtype**. Exact subtype is only scored when publisher type is a real production `photoTypes(category)` label. Accepted broader subtype families are separately recorded with original manifest `acceptedTypes` if present.
- Color labels were never independently recorded on this 16-photo cohort, therefore **zero primary-color correctness claims**. No per-image results used for setting weights/thresholds. Missing, timeout or review results count as coverage losses; a conservative abstention does not mean automatic recognition is correct.
- Actual browser runs upload **only sanitized numeric and source-ID metadata**, no JPEGs/screenshots/owner identities. No network POST, original photo source bytes in requests or public hosting. The same phone checker/worker used in P833 is unchanged. Four browser-half runs are automatically aggregated into a source-wise per-category and cross-browser failure report. The aggregator rejects missing/duplicate/reordered source IDs, fabricated positives, invalid categories/types, wrong conservation, incomplete browser fixtures, unexpected outbound image upload and missing sources.
- Three additional adversarial synthetic audit tests preserve source completeness and denominator, reject fabricated positive/negative and subtype, and make clear that same model abstention in two browsers is not equivalent to a correct label.

## Acceptance / what can be concluded
A numerical real-model score from *these sixteen publisher originals* can legitimately identify which categories and source IDs fail. It CANNOT establish accuracy for a spouse's real phone garment photos, whole-outfit segmentation, primary-color correctness, independent blinded accuracy, or a safe live authenticated wardrobe. Any candidate classifier change in future must be validated on **new** separately chosen and independently labeled material, not tuned to beat these development-exposed 16.

Dedicated no-deploy CI must report exact-head **six jobs** success: exact P833 green parent, 4 strictly allowlisted scripts/test/report/workflow paths (no public app changes), 280/280 Node regressions expected, four real unchanged original model runs (Chromium + WebKit × two halves), and fail-closed numeric-only aggregate. No deployed preview or invitation is made here. **Family Alpha HOLD #255 remains OPEN.**
