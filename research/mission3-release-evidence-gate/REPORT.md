## Why this is a real Mission 3 blocker

The existing `public/device-check-engine.js` exports a privacy-filtered `closet-current-device-check` JSON report containing a 12-hex **recognition asset version**, platform derived from the browser user-agent, ten manually checked pass/fail steps, and up to 40 structured diagnostic events. This is useful owner QA but **does not certify physical phone hardware, original JPEG round-trip integrity, signed live hosted cloud or four-account integration**. Synthetic Chromium/WebKit at CSS widths 320/390/430 and disposable signed PostgreSQL cannot satisfy Family Alpha #255's independent release gates. Earlier `docs/PHONE-PHOTO-VALIDATION.md`, `docs/CLOUD-BACKUP.md` and the physical-phone Issue #970 likewise distinguish real phones from desktop emulation.

The new `research/mission3-release-evidence-gate/verify.mjs` adds an **offline, privacy-safe, falsifiable evidence-preflight tool**, not another claim of test completion. It checks evidence completeness, shape, local artifact SHA-256, permitted report fields and expected original/saved/restored SHA receipts. It never connects to a network, verifies a hosted service by itself, approves release, or removes HOLD #255.

## How to use on an owner-authorized real device/cloud QA session

1. Run `node research/mission3-release-evidence-gate/verify.mjs --template > /PRIVATE/FOLDER/mission3.json`. This creates **NOT_RUN** values, no pretend PASS.
2. On a **physical Android phone running Chrome** and a **physical iPhone running Safari**, use the owner-controlled private development/test build. Record the actual browser/OS versions, UTC test timestamp and exact integrated source Git SHA. Export the existing My account → Device check JSON after its ten manual tasks and at least one recorded saved-recognition diagnostic. The report's 12-character `appRelease` is a recognition-asset version, **not** the 40-hex Git commit; set the manifest's `appAssetRelease` to that actual exported value.
3. Record 15–40 **distinct owner-consented** original camera/gallery JPEG SHA256 digests **as persisted by the app** per device. Compare each one against the saved and the restored byte-identity receipt. These hashes must be derived from actual JPEG bytes, not from a visually similar recompression or merely a user-entered mock value. Preserve source private receipts locally. Do not upload original garments or private backup JSON to GitHub. If no independent authorized SHA access is available, leave the gate **BLOCKED**.
4. On a separate **explicitly owner-authorized** hosted testing environment (not default production and not disposable local Postgres), use **four separate test accounts** represented only by aliases `tester-1` through `tester-4`. Record signed JWT read/write authorization and denial of cross-owner/anonymous metadata/photo access; double-JPEG SHA, revision CAS, explicit cancel, conflict/no-merge, atomic restore/reopen and four-account isolation. Make a **redacted**, manually audited `closet-current-mission3-cloud-check` JSON with only `format`, `version`, `environment`, `testAccounts`, and `passedCases`.
5. Verify a **single compatible integrated build** actually exercised Mission 1 owner-approved recognition → Mission 3 authenticated private wardrobe → source-verified outfit → Mission 2 source-3D quality gate or original-photo 2D fallback → lossless cloud backup/restore. Record the three exact mission commits and integrated commit in a redacted `closet-current-mission3-integration` JSON with `format`, `version`, `sourceHead`, and `passedCases`.
6. Store the redacted device, cloud and integration JSON receipts in the same **PRIVATE** directory as `mission3.json`; compute SHA256 over the exact bytes of each receipt, copy those hashes into its fields, fill required case outcomes with PASS/FAIL/NOT_RUN/BLOCKED, and run `node research/mission3-release-evidence-gate/verify.mjs --verify /PRIVATE/FOLDER/mission3.json`. For incomplete evidence it returns `BLOCKED` and process exit 2; for *fully populated, internally consistent* evidence it returns **EVIDENCE_READY_FOR_INDEPENDENT_REVIEW**, *not* verified hardware, hosted-cloud security, GO, or deployment authorization. Its `releaseAuthorized` is **always false**.
7. Have the owner/independent reviewer inspect actual devices, hosted access receipts and sensitive originals **outside** this text-only checker; keep real private photos and account details out of public GitHub. An SHA digest only proves a supplied artifact was unchanged after being recorded; it does **not** establish the truth or provenance of the assertions inside it. A self-entered `execution:"physical"` or `environment:"authorized-hosted"` also does **not** prove actual hardware/hosting.
8. Only a later explicit release decision following all real-world acceptance may change [HOLD #255](https://github.com/nickhaney916-lang/Closet-Current/issues/255). This tool neither releases nor sends invites.
