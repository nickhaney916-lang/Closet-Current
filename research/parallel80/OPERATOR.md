## Evidence interface for #67 / #68 / #69 / #70

`public/subtype-review-80.mjs` provides `evidence80`, `decide80`, `createReview80` and the versioned `CONFUSIONS` map. Evidence pins the exact original JPEG SHA-256, actual recognition-input JPEG SHA-256, item/physical-unit ID, original/crop/segment/unit/companion revision digest, mask receipt and descriptor digests, pseudonymous owner scope and ephemeral reviewer session. For segmented items the existing #70 source/mask receipts and owner-confirmed unit status are mandatory; paired shoes also require two distinct same-source masks and actual owner grouping confirmation. Hashes bind bytes and receipts, not semantic mask correctness.

`public/subtype-worker-80.mjs` consumes the existing pinned FashionCLIP scorer, never a replacement model. It checks request opt-in and input SHA, executes two complete frozen-vocabulary comparisons including nonclothing controls, and returns no `identified` event or strong subtype. Model evidence contains `ff13/fashion-clip`, exact model revision, vector SHA and a deterministic digest of eight relevant recognition-source modules. Main-thread expected model/source metadata must agree with the worker, and every field is rechecked against the current live item before applying a manual choice. A returned numeric `score` is a vocabulary-relative score, not an empirically calibrated likelihood.

The core policy returns at most three alternatives, always `itemType: Unknown`, `requiresOwnerConfirmation: true`, `automaticallyCertified: false`. Strongly separated same-category scores can produce `status: hypotheses`, never an automatic subtype certificate. Close scores in either framing, cross-category or negative winners, missing full vocabulary, invalid numbers and inadequate detail abstain. Tiny residual candidates are excluded. These frozen thresholds are engineering controls, **not #71 calibration**.

## Continuation: ephemeral approval capabilities and real-worker smoke

`decide80` returns deeply immutable, in-memory issued decisions. `createReview80` accepts only the original decision object from the same loaded module, bound to the exact original evidence. All handles share one consumption/revocation state; closing one revokes the others. Cloning or deserializing a diagnostic cannot grant approval, and changing a caller's evidence cannot rebind the issued capability. Independent evaluators can serialize frozen diagnostics for private analysis but must never treat them as reusable owner confirmation. Invalid clocks, rollback before issue and age over 60 seconds fail closed.

Source-module GETs and the model-manifest GET have individual five-second deadlines; module body reads stop above 250,000 bytes, before retaining an unbounded response, and reject invalid UTF-8. Photo decoding also times out. First-use existing model downloads can take longer; these limits do not promise physical-phone performance or abort the general runtime owned by #69.

Run `node scripts/test-parallel80-real-worker.mjs` in an environment permitted to download the existing pinned public model/runtime. It starts a local static server, creates one geometric JPEG in memory, and exercises the **actual worker/model**, not a scorer callback. It verifies opt-in before setup, exact full-vocabulary score shape, source/model provenance, byte preservation, mismatch rejection and no HTTP uploads. Only aggregate results and code/model hashes are printed; no predictions or input pixels are exported. Network/model unavailability is a test failure/BLOCKED execution, never a synthetic pass. A successful run establishes that the code path executed, **not subtype accuracy**: the generated image has no human garment label and cannot contribute to any real-photo denominator. Dedicated CI runs this smoke separately from the six synthetic-scorer UI tests.

## Detail preflight and strict evidence packets

The existing detail gate now runs before model setup/comparison in the panel. A dim/flat or smaller-than-224-pixel image stays available for normal manual review and an Unknown subtype save; no model request is issued for those already-ineligible detail cases. These frozen pixel flags are conservative engineering proxies, not independently labelled photo quality or an instruction to delete/retake every dark garment.

Use `evidence80` to construct the request capsule. Its exact own data fields are `schema`, `ownerId`, `sessionId`, `itemId`, `sourceSha256`, `inputSha256`, `revisionSha256`, `maskDescriptorSha256`, `maskSha256`, `unitId`, `unitStatus`, and `segmented`. Do not add raw photos, labels, rater information, confidence, notes or other diagnostics to this capsule. IDs must be nonempty strings of at most 128 characters; hashes are strict SHA-256 strings; `segmented` is Boolean. Segmented receipts require a mask hash and an existing confirmed unit status; single-photo receipts use null mask and `single-photo-owner-reviewed`. Accessors and malformed/extra properties are rejected. These fields bind the existing workflow; they do not confer real account, person or mask-truth authority.

The actual worker validates this capsule and the input JPEG digest before invoking model setup. The adapter revalidates and snapshots it before either scorer call. Changing the caller's object during asynchronous scoring cannot change the receipt identity. Invalid packets remain unavailable/Unknown and must be corrected deliberately, not coerced into a valid source or human annotation.
