## Why the recognition model needs better labels before more retraining
[PR #905](https://github.com/nickhaney916-lang/Closet-Current/pull/905) verified exact final head `d2fc332f4c9b9b417da8172ef87a7dd1aaab4194`, [GitHub CI #43155085921](https://github.com/nickhaney916-lang/Closet-Current/actions/runs/43155085921), **3/3 PASS and 283/283 application regressions**. Genuine pretrained Marqo q8 model trained separate supervised prototype classification heads on **32 original SHA-verified existing publisher garment photos**, then evaluated **16 source-ID/SHA-disjoint BUT development-exposed real photos**. The supervised variant was **WORSE** than original fashion zero-shot: category 9/13 vs 12/13, subtype/family 6/13 vs 8/13, nonclothing 0/3 in both. Two newly correct subtype suggestions and FOUR previously correct lost. **REJECT promotion**.

The training set explains why: **Tops had only two T-shirts, no blouse/sweatshirt/tunic; Dresses had only two generic “Dress” images; Accessories and nonclothing had no training images**. The target confusion classes are unrepresented. More prompt perturbations, confidence thresholds, tiny supervised fits or test-infrastructure enhancements will not fill missing visual ground truth.

## New work: accelerate acquisition without inventing labels
This M5 branch stacks only on the **verified P67-02 fashion model parent**, not the rejected M4 prototype. `scripts/parallel67-commons-source-intake-05.mjs` searches the official Wikimedia Commons search/imageinfo APIs for nine **candidate source pools**:
T-shirt, Sweatshirt, Blouse, Tunic, Sneakers, Boots, Dress, Skirt, and **nonclothing**. These are *search queries*, not original image class labels.

The script screens file namespace, JPEG/PNG/WebP MIME, minimally usable dimensions, 20MB original-source cap, Commons original SHA1, HTTPS upload.wikimedia.org preview, currently listed CC0 / CC BY / CC BY-SA (2.0–4.0) license string and original Creative Commons license URL. Only Commons is queried; nothing is downloaded from an arbitrary submitted host. Images are NOT downloaded or uploaded. Wikimedia metadata by itself is **not** a final commercial-use determination: original source rights and attribution obligations require manual verification.

Each result is exported as a **quarantined candidate** with source Commons page, listed license, source SHA1 and a photo preview link. Every result deliberately has **null category label, null subtype, null human color, null image SHA-256, null reviewer IDs, null train/dev/test split** and `status=quarantine_not_training_ground_truth`. This distinction is essential: title/search tag does NOT constitute an independently approved human label. Existing 59 published source titles and duplicate page IDs/hashes are excluded. No quarantined file may be fed to actual training or cited as new blind validation.

Adversarial tests reject NC/ND/unknown licenses, unsafe image hosts, non-image content, malicious HTML/license metadata, missing source identities, duplicate source instances, forged human labels and an attempt to bypass the quarantine. Dedicated no-deploy CI validates the exact green P67-02 parent, only **four** new research/test/docs/CI paths, all existing native app tests, and attempts a genuinely live Wikimedia metadata search. Only metadata JSON is kept in artifact; NO photo bytes, model weights, private accounts, owner filenames, cloud data or personal original JPEGs are published.

### Human-label acceptance criteria still required (NOT MET by this script)
1. Two **genuine independent human reviewers** inspect source image pixels, classification category and subtype, broad garment vs household/nonclothing, primary color, background and person/face presence, and agree *before* any model sees new test labels. AI-generated guesses, filename/source title or fake reviewer IDs cannot substitute. Preserve disagreement, abstentions and ambiguity.
2. Verify each source's actual downloaded original JPEG SHA-256, per-image license, author/attribution and commercial rights, and any potentially identifiable people's reuse rights. Quarantine until approved; avoid training on people or unlicensed stock images merely because they appear in Wikimedia search.
3. Freeze train/dev/sealed-test by original image SHA to prevent duplicates. A separate independent gatekeeper must hold sealed evaluation labels outside model-development CI. Do not make previously evaluated original 16 photos into a new “blind” test just because they weren't included in M4 training.
4. Aim for dozens of correctly labeled original cases for T-shirt-vs-sweatshirt, blouse-vs-tunic, sneakers-vs-boots, dress-vs-skirt, and negative examples, with sufficient counts for both training and truly held-out evaluation. Document actual denominator and class imbalance.
5. Continue classification using a locally verifiable model with review for missing classes and negative rejection; integrate only when new independent subtype/category/color and false-auto-save evidence improves, physical Android/iOS memory/latency is acceptable, and main controller authorizes integration under existing Family Alpha HOLD.

**Alternative discovery data:** Official [Open Images V7](https://storage.googleapis.com/openimages/web/factsfigures_v7.html) has human annotations under CC BY 4.0 and image sources listed as CC BY 2.0 with explicit per-photo rights uncertainty. It can help coarse clothing/negative detection, not reliably supply fine blouse-versus-tunic truth. [Fashionpedia](https://fashionpedia.github.io/home/data_license.html) licenses annotations and ontology CC BY 4.0 while individual underlying image rights require separate checks. Do not silently treat any dataset's annotation license as blanket commercial permission for the photos.
