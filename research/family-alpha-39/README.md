# Work 39 — smart capture research prototype · HOLD

A separate, localhost-only prototype shows capture guidance, checks a small decoded sample in the browser, and gives **Use Photo / Retake Photo**. A single camera frame or chosen file is held in memory. A timed mode pauses for a decision after each frame; it is a research interaction, not the existing unattended continuous-capture flow. Use holds the original chosen File or the camera's captured JPEG Blob in memory, but does **not** save to a wardrobe or start indexing. Stopping/page exit releases the camera and page memory. No network, provider, account, avatar or app source is modified by this prototype. Do not deploy or integrate it.

## Measurement and limitations

Image dimensions are measured from the decoded image. Local 128-pixel sample measurements are dark and bright pixel fractions, luminance contrast and Laplacian variance. Thresholds are exploratory: lighting, low-detail fabric, patterns, deliberate dark clothing, and resampling can cause false positives or negatives. The UI displays at most one advisory and always permits a readable photo to be used. A failed decode offers a choice, not automatic deletion. The system cannot infer cropped sleeves, glare vs white fabric, shadows, background clutter, orientation, multiple objects, pair-of-shoes status, actual focus, or pixelation reliably; it asks the user to visually check framing and obstructions rather than claiming detection. It does not upscale or synthesize clothing.

The existing #333 public capture code requests 1920x1080 video and renders a frame to a JPEG with max dimension 2048 and quality .94; this is not a full camera-sensor original. `photoToJPEG` also decodes, resizes to <=2048 and recompresses imports. This experiment leaves those paths and duplicate behavior untouched. Its selected-file preview uses the file Blob without re-encoding; its camera capture necessarily encodes a video frame, not an original full-resolution camera still. Existing privacy, recognition inputs, saving and transaction recovery are not verified by this standalone prototype.
