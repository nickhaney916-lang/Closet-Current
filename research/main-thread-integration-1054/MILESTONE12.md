## Three identical research arms, no source/label compromises

The new `scripts/test-main1054-webkit-sampler-ablation.mjs` is source-forked from the current M11 genuine q8 model, owner/source SHA, and P880 research harness. It accepts an explicit `MAIN1054_MEMORY_MODE`, restricted to:
- **`none`**: no Linux `/proc` inspection or periodic sampler. Source-locked Commons original JPEGs, true pretrained ONNX/WASM worker and safe native owner review still run.
- **`rss`**: sample Linux browser process-tree descendant `VmRSS` through `/proc/<pid>/status` every 3s, **without** expensive `smaps_rollup` page-table PSS reads.
- **`pss`**: same RSS sampling plus `smaps_rollup Pss` for descendant processes when readable, corresponding to M11's heavier sampler.

In each arm, FOUR genuine public-original photo attempts (0035,0062,0078,0059) run in one continuous desktop WebKit page and one synthetic signed owner, with genuine both FashionCLIP+FashionSigLIP q8. True source/original SHA, owner review consent, M1 P880 low-risk exact jointly top-ranked manual-safe suggestion policy, and no private save/approval/admissions preserved. Separate identical-source desktop Chromium two-photo `none` control rules out a broken research runner. Exact source SHA/weights, image licenses and local-only GET network audit unchanged. All arm records have unique mode-specific JSON names, actual completed numerator/denominator, per-model load/infer phase durations and error stage, observed page crash/disconnect, worker lifecycle and sampled-memory limitations. Data artifacts include **only numeric/public original source id/hash**, no JPEG image bytes, model weights or owner photos.

**Causality limitations:** sequential same-run modes may differ in ambient OS scheduling, model cache behavior or CPU load. One successful none arm and a failing pss arm could support a sampling-perturbation hypothesis but would not prove which memory operation is responsible. Summed RSS double-counts shared pages; sampled PSS may be incomplete, not OS high-water or actual iPhone Safari resident memory. Never call this an OOM diagnosis without direct OS/worker error evidence. An incomplete 4-photo arm is marked `BLOCKED_INCOMPLETE` even when diagnostic packaging succeeds.
