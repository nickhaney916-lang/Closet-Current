# MAIN1054 Mission 4 Milestone 8 — bounded real q8 WebKit stage diagnosis

## Why this independent experiment exists

The pinned [M7 draft #1084](https://github.com/nickhaney916-lang/Closet-Current/pull/1084), exact source HEAD f3a09ee10879b15ad6b8dc84af2805b2ee679363, runs up to sixteen genuine sequential dual-model recognition attempts in ONE desktop Playwright WebKit page, but its dedicated actual-model step was still running at the last observed [M7 Actions #43531280108](https://github.com/nickhaney916-lang/Closet-Current/actions/runs/43531280108). The complete M7 native privacy job DID pass 17/17 exact owner-original tests, 48/48 native Chromium/WebKit P876 risk/consent browser cases, 12/12 original JPEG 2D preview browser cases and 2,003/2,003 full native regression tests, zero failures. The WebKit test's elapsed time alone is NOT a crash, hang diagnosis or successful photo denominator.

Source inspection identifies a concrete *diagnostic latency issue*, not yet a diagnosed memory or model error: existing `browserRequest82()` defaults to up to **240,000 ms** before returning P82_TIMEOUT, while the M7 browser runner can wait **290,000 ms** for a single image. A stalled worker can therefore cause a long no-result interval and obscure whether a first or later model inference was reached.

The independent M8 research experiment does not change the native app, P82 worker, production source, model weights, owner authorization, original JPEG, backups, 2D fallback, staging/production, hosted Supabase or a sibling mission. It is stacked on M7 exact immutable HEAD. THREE new paths only: this engineering protocol, a new bounded real-model browser runner and a dedicated no-deploy CI workflow.

## Bounded test and evidence

- Only source-sha and Commons-license verified `commons-0035`, `commons-0062`, `commons-0078`, `commons-0059`, in the same source-extracted genuine M4 native clothingFields signed-owner research dialog, using exact M1 P876 owner review and empirically risky label abstention.
- Genuine pretrained FashionCLIP and FashionSigLIP q8 ONNX/WASM initialized from original immutable P82 model artifact and text locks; no mock observations, private account, hosted cloud, saved garments or customer photos.
- Actual browserRequest82 receives `timeoutMs:45000` for *this test only*; original app transport behavior remains unchanged. The browser harness waits a maximum 60,000 ms for each attempted result. This is a diagnostic fail-closed budget, **not a validated safe browser performance threshold**; a slow valid inference can be conservatively recorded as timeout and must not be mislabeled a model defect or incorrect class.
- WebKit continuous desktop browser, four sequential attempts (one signed synthetic owner, one page), observes actual model worker stages: Preparing local comparison, Comparing first model, Comparing second model, when they are emitted. Each attempt records completion, last known progress stage, source id/hash, worker lifecycle, explicit failures, observed page crash/close vs timeout. No unsupported automatic retry, no private storage write, no owner final confirmation.
- Separate Chromium same-origin two-attempt comparison to validate runner and distinguish browser-specific failure. Both results are de-identified public development diagnostics, not blind accuracy, physical iPhone results or live account acceptance. Browser-process RSS and root cause remain NOT MEASURED/UNKNOWN unless directly instrumented.
- Local HTTP GET and same-origin WebKit blob runtime requests only, forbidding external model fetch/upload. Numeric-only diagnostics artifact; never upload public raw original JPEGs, model weights, or owner photos.
- If a browser yields 0, 1, 2 or 3 of 4 attempts, the reported test status is BLOCKED_INCOMPLETE even if the GitHub diagnostic packaging step is green. The product remains disabled for actual WebKit owner inference regardless of desktop evidence.
- Independent source-only CI validates immutable parent, three-path research scope, no deploy, offline build and full 17+48+12+2003 owner/privacy checks. Real-model ephemeral CI materializes sources/hashes and runs bounded WebKit 4 and Chromium 2 jobs.
