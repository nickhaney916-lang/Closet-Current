# Work 42 — original-photo outfit board research / HOLD

An isolated diagnostic component displays source-verified original JPEGs as an **Outfit combination**, clearly labeled not a virtual try-on. It uses contain sizing, no invented pixels or recoloring; shoes are shown as the original reference photo. Missing, wrong-owner, mismatched SHA, invalid framing, failed decoding, stale session or account changes lead to **REVIEW REQUIRED**, never a partial misleading outfit. Successfully checked originals lead to **PHOTO PREVIEW**. Untrusted `wornApproved` flags have no effect. **WORN PREVIEW is deliberately unavailable**: there is no independently verified, source-and-combination-bound visual approval mechanism in this prototype. Designing such an authority and verifying its provenance is a prerequisite for enabling it; simply supplying a boolean or passing tests cannot grant approval.

Integrity checks rely on *trusted upstream* owner, session, and original-photo hash. This research component does not authenticate a user, query account ownership, establish that an externally supplied hash is trustworthy, remove metadata, or prove IndexedDB isolation. The demo uses a fake owner for licensed public images, never real accounts. An actual integration must receive verified owner-scoped item references and source hashes from the existing authenticated app boundary; do not pass client-asserted values and call them authorization. All board URLs are local Blob URLs, revoked on clear/disposal; session/pagehide events clear the board and stale async work cannot draw. This is not connected to the current three-outfit UI, recommendation engine, outfit swap/favorite/reload, or actual app storage.
