## Concrete source defect

`recognitionSuggestion42` was saved with `sourcePieceKey` (original source SHA + manually rounded or detector-assigned **instanceKey**) and `cropBounds`, but **not the actual reviewed crop JPEG SHA or worker version request tag**. A detector's `seg-...` key stays constant even after a crop redraw; merely matching bounds/key does **not** identify the precise input pixels the local FashionCLIP actually saw. An optional stale/misassociated model suggestion could thus remain misleading in an otherwise valid and correctly human-confirmed record. Without any requested model asset tag it was also more difficult to compare successive Work #34 classifier research outputs. This is evidence-trust/reproducibility, not garment-accuracy improvement.

## Narrow implementation

- In existing `recognition-review-42.mjs`, use existing `source-proof.mjs` `jpegBytes` and browser-native `digestBytes` to SHA-256 the **actual JPEG crop bytes**, while binding to the already canonical source JPEG SHA. Return `inputBinding49:{sourceSHA256,cropSHA256,requestedAssetTag,hashAlgorithm:'SHA-256'}`. Tag is a bounded copy of the **requested worker URL cache/version query**; on empty/unsafe value, use `unversioned`. **This is NOT a cryptographic attestation of FashionCLIP model weights, build identity, or prediction truth.** Don't claim that a mere URL query proves the model hash/version.

Attach the input binding only to a completed local model proposal; never use it to confirm category, subtype, primary/secondary color or the garment itself. Preserve legacy model suggestions that lack a binding as explicitly **unbound** for backwards compatibility; never silently create a hash for historical predictions after the fact.
