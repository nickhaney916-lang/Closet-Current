Existing source-preprocessing and model weights remain unchanged.

## Standalone research implementation

`research/original-context/original-first-index-gate.mjs`:

1. Validates JPEG content-addressed source bytes and calculates SHA-256 of the **first app-retained JPEG** (not raw camera sensor/native upload bytes), in a caller-provided owner/generation session. It rechecks the synthetic owner across async decoder, color sampler and independent classifier calls. It does not trust an editable garment owner label.
2. **One garment:** selects `originalPhoto.image` when retained, else current `item.image` (first saved source). Independent main/confirmation classifications use that original frame, not a potentially masked preview.
3. **Outfit photograph:** requires the shared full `originalPhoto.image`, explicit `outfitSourceId`, unmasked `recognitionPhoto.image`, safe `cropBounds` and non-clipped segment hints. Derives a **native-resolution unmasked pixel crop directly from the decoded original frame**, passes the crop only to the classifier, and uses the original-derived mask for color sampling. The global scene is **never used as the garment label**. The source-region mapping comes from preexisting segmentation coordinates; without independent ground-truth correspondence it is *not proof the detected box belongs to the intended garment*.
4. Automatic exact type indexing requires **two independent corroborating decisions**. Shorts/skirt, shoe family and dress/skirt conflict tests abstain safely on disagreement: for same confirmed broad category and source-local color it returns `indexingLevel:'category-color', itemType:'Unknown'`. Cross-category conflicts or invalid colors require manual review. Optional pattern is retained only when independent views agree; optional failures do not erase safe category and color. The helper **never writes or autosaves**: product integration would need an owner-reviewed, backward-compatible save policy.
5. Exposes source-preserving pixel-exact crop from original (no resizing, rounding only at pixel boundaries), with binary mask validation and no source mutation. JPEG encoding of stored original may itself already have lost native camera file metadata or detail.
6. Adds `auditOriginalOutfitRegions`: checks 1–12 synthetic capture pieces for duplicate garment IDs, capture frame consistency, identical shared original allowed, valid separate bounded instances, missing raw preview, and heavily overlapping instances. Overlap flags **review**—a top overlapping a jacket may be real, so no piece is deleted or silently combined. No image URLs or pixel arrays leak into returned diagnostics.

This is an *isolated proposal*, not connected to real Auth, real segmentation inference, or production saved-clothing indexing. Color sampling in browser tests invokes **existing** `public/photo-color.js` `maskedPalette`, not a new invented color-classifier.

- `tests/original-first-index-gate.test.mjs`: single full-source priority, unmasked multi-piece region selection, duplicate/overlapping segments, source-version replacement with identical preview, shorts/skirt, jacket/coat, shoes vs non-shoes and dress/skirt disagreement, category+color fallback, optional pattern failures, masked original color, exact source RGB preservation at full native dimensions, corrupt/blank/mismatched images, camera crop bounds, tiny masks, user corrections, async owner switches. Never uses actual customer/licensed photos.
- `scripts/test-original-context-mobile.mjs`: generates real synthetic 256×384 JPEGs in-browser; decodes using the browser image decoder, calls existing maskedPalette on a left-side red garment region versus blue scene, compares every 128×384 source-derived pixel to decoded original, verifies no whole-scene classification on an instance and blocks shoe cross-category guesses. Runs Chromium/WebKit at 320,390,430 CSS pixels; 2D/3D code is neither imported nor touched.
- `scripts/compare-original-context-synthetic.mjs`: deterministic 16-case **MOCK classification** head-to-head. The "before" is an explicitly controlled single-preview guess, not a current production model run. The "after" runs the source gate with assigned independent synthetic judgments. As measured in CI: **before category 11/16 = 68.75%, exact subtype 4/16 = 25%, wrong auto-indexed subtype 12; after category 15/16 = 93.75%, exact subtype 12/16 = 75%, wrong accepted automatic subtypes zero**, with 3 safe category+color reviews and one fully withheld for cross-category disagreement. This demonstrates a controlled **decision-policy safety improvement only**, **not true model accuracy**. Image pixel integrity remains 16/16.
- `scripts/check-original-context-historical.mjs`: runs the existing `checkRecognitionRegressions` against 32+16+11 committed **historical prediction JSONs and manifests**. It deliberately does **not** load or infer on any of their real/public licensed JPEGs. The original committed metadata is unchanged: **59 prior predictions, 56 clothing, 43/56 = 76.79% category, 27/56 = 48.21% exact subtype, 36/56 = 64.29% accepted subtype, all 3 negative controls rejected**. These historical prediction files have a different source/inference checkpoint from the later PR #234 report: **47/56 = 83.93%**, 35 automatic subtype choices and 12 category-only reviews on its verified #226 artifact. **Do not compare the two historical numbers as before/after, or claim any actual recognition accuracy increase in this branch**.

It explicitly source-fences production `public/`, `benchmark/`, and `supabase/` unchanged. No paid model or external network. Raw output artifacts are marked NO DEPLOY.

## Limitations and release/integration blockers

1. The live model's true classification accuracy, segmentation mask IoU, shorts/skirt, boots/shoes and dress distinctions, camera lighting/real color and physical Android/iPhone image fidelity **have not been newly measured**. Fixing the admission policy does not train/improve FashionCLIP itself. PR #224/#226/#234 retain existing historical release veto; future results must pass independent 59-photo, licensed holdout, and human annotation gates.
2. Native/retained original semantics need agreement with #233 provenance and actual cloud manifest. Current first in-app JPEG may already have been resized/re-encoded; SHA alone does not prove untouched native file or accurate segmentation coordinate mapping. Crop origin/bounds for multi-piece must be connected to validated region/mask and face original dimensions.
3. Real photo segmentation, high-resolution mask contour/hair/thin sleeve detail, occlusions, multiple people in one scene and near-identical shorts/skirt silhouettes remain unsolved. Duplicate/overlap flag only requests review, never predicts a garment class.
4. A false primary color, unverified color, or conflicting independent classifier result stops auto-index or limits to category+color. This conservative choice may **reduce automatic indexing coverage** in real life; human review and representative testing are required. Never invent material, fabric, fit, brand, print or subtype to fill optional fields.
5. Browser tests are headless Chromium/WebKit in phone-sized viewports—not a physical phone or live customer app. No training assets or new model tokens/GPU purchased.
6. The user-facing app is unchanged. Integration would require consent, real authenticated source ownership, source image/region linking, confidence controls, versioned saved-photo snapshots, saved-closet regression and physical-device tests. **Main Closet Current conversation owns integration/release**.

**Disposition:** safe isolated original-first admission/indexing prototype + measurable offline synthetic behavior. **HOLD** runtime adoption until independent validation and explicit main conversation integration approval.
