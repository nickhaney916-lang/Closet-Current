Local build PASS; full regression **1,657 PASS / 0 FAIL / 3 existing SKIP**

recorded in issue #201 / the draft PR, separately from these local results.

Fixtures contain two fictitious owners, comparable-looking records with the
same IDs but distinct source bytes, and generated 2×2 JPEG swatches only. This
is a saved-record/selection benchmark, **not** an end-to-end camera/recognition
benchmark or a visual garment-quality dataset. An independent ledger binds
owner, source ID, original/crop/display hashes, color and type. Fixture admission
rejects foreign/blank/remote/duplicate records and personal fields; image values
must exactly match generated bytes. No real human/garment/selfie photo is used.

The oracle independently checks owned IDs, unique slots, unchanged source/color/
type, pin inclusion, dress incompatibilities, jacket/coat placement and no shopping
placeholders. It does not reuse the product's signature or missing-slot routines
as its sole truth. Negative controls verify that invented IDs, duplicate slots
and changed source bytes fail. The engine itself assumes caller-scoped input;
fixture admission and UI/database tenant checks are separate boundaries.

## Browser evidence contract

`scripts/test-issue201-outfit-browsers.mjs` serves only the built local app and
uses real Chromium/WebKit IndexedDB. Synthetic Auth names disable cloud sync;
all remote requests are blocked. Repository figure images are replaced with a
generated swatch; model/binary/API downloads are blocked and no selfie picker
is opened. No claim about actual figure appearance follows from this harness.

The actual Style this button creates three options; one shoe swap changes only
that slot; actual Save outfit survives page reload with its pin. Actual backup
download/import handlers restore a same-ID conflict, preserve the existing red
record, remap the imported blue pin and retain original/crop/source values.
The restored board survives another reload. Identity change with stale DB is
refused; switching to B shows an empty separate closet, B saves the same-ID
fixture, and returning to A recovers only A's saved outfits/source hashes.

Browser results are written to `artifacts/issue201/browser-results.json` with
engine, source hash, explicit synthetic/physical/realistic limits and blocked
request counts. Playwright is available in the host runtime but browser binaries
are absent locally, so final browser evidence must come from the dedicated
exact-head GitHub workflow, not an assumed local pass. It downloads browser
emulators only, no paid model or inference weights.

## Recommendations / release limits

Central owner should extend prepared-source validation to original photo,
recognition crop and provenance changes, and establish a product-level invalid/
blank-photo policy before claiming an unconditional owned-photo quality pass.
Mixed-owner records must never reach the scorer; it is not an authorization
layer. This benchmark cannot prove hosted RLS or real-account isolation.

Subsequent opt-in paid try-on evaluation requires separate owner authorization,
an approved capped budget, rights-cleared detailed model assets, privacy/retention
and consent handling, independently annotated held-out garments and explicit
logo/color/fabric/shape/fit fidelity criteria plus physical-phone validation.
No exact fit, sizing, logos, fabric fidelity, industry-leading realism or 100%
recognition claim is supported by synthetic swatches or reused fixtures.

No app/backend/deployment code is changed. Main conversation alone decides
integration. Existing deletion/privacy/accessibility/hosted/photo-accuracy gates
remain separate and unresolved. No merge, deploy, production/Supabase change,
customer data, spending or paid AI activation is authorized by this report.
